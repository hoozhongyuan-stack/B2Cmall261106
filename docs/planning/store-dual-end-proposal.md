# 门店双端方案提案：总部 PC 运营台 + 门店小程序工作台

> 状态：待评审　｜　日期：2026-11-09　｜　范围：PC 后台信息架构调整、小程序新增「门店中心」

## 1. 问题诊断

### 1.1 现状

| 端 | 现状 | 问题 |
| --- | --- | --- |
| PC 后台 | 同一套后台承载 SUPER/OPS/CS/WMS/STORE 五种角色，STORE 账号登录后只能看到 5 个菜单，还需要在顶栏「切换门店」 | 1）总部视角混入门店操作，菜单 8 组 30+ 项，路径深<br>2）「切换门店」是全局隐式状态，订单/自提/配送/库存四个页面都要读它，用户容易忘记自己当前在哪个门店<br>3）门店一线场景（核销、接单、改库存）发生在店里，用电脑不现实 |
| 小程序 | 个人中心只有会员/积分/优惠券/售后/地址等消费侧入口 | 门店员工没有任何工作入口 |

### 1.2 结论

两件事本来就不是一个产品：**总部要的是「跨店汇总 + 批量 + 配置」，门店要的是「本店待办 + 即时操作」**。把它们塞进同一个后台，复杂度就不可避免地外溢到每个页面。

## 2. 目标形态

```
总部（PC 后台）                     门店（小程序）
─────────────────                  ─────────────────
全量数据 · 跨店对比 · 批量处理        本店数据 · 待办驱动 · 单手操作
配置门店规则 · 发邀请给店长           核销 / 接单 / 送达 / 改库存 / 看板
无「切换门店」概念                    有「当前门店」概念（登录即绑定）
```

两条原则：

1. **PC 不出现「当前门店」**——所有门店相关数据统一以「门店」列 + 门店筛选表达，一次看全、按需收窄。
2. **移动端一屏一任务**——工作台只回答一个问题：现在要我做什么。

## 3. PC 后台改造（只做总部）

### 3.1 移除门店切换

- 删除顶栏「切换门店」下拉及其本地存储（`getActiveStoreId` / `setActiveStoreId`）。
- 订单、自提、配送、库存等页面不再依赖隐式门店上下文，改为显式筛选条件。
- 门店业务在 PC 全量可见；STORE 角色不再能登录 PC（见 3.4）。

### 3.2 菜单收敛

| 现状 | 调整后 | 说明 |
| --- | --- | --- |
| 履约：自提核销 / 同城配送 | **门店与履约**：自提核销 / 同城配送 | 与门店合并为一组，减少分组噪音 |
| 门店：门店管理 | 门店管理（含库存、看板） | 库存与看板从「更多」菜单提升为详情抽屉 Tab，不再跳页 |
| 交易：所有订单 / 批量发货 / 售后 / 评价 | 保持 | 订单增加「门店」列与筛选 |
| 8 组 | 7 组 | 目标：任何门店相关任务不超过 2 次点击到达 |

### 3.3 页面级整合（重点）

**订单列表**

- 新增「门店」列（固定在订单号右侧，超宽时横向滚动仍可见）。
- 「门店」筛选改为多选：可一次看 2~3 家门店。
- 批量发货按门店自动分组展示：`昆明五华店 8 单 / 昆明盘龙店 3 单`，避免发错门店。
- 表头增加门店维度小计（当前筛选下的门店数）。

**自提核销**

- 列表新增「门店」列 + 门店筛选；默认按时间倒序。
- 顶部保留「扫码/输码核销」输入框（总部代客核销场景）。
- 支持按门店导出待核销清单（P2）。

**同城配送**

- 新增「门店」列 + 门店筛选 + 超时未接单 tab。
- 批量接单弹窗显示「涉及 3 家门店」，并要求选择配送员。

**门店管理**

- 列表新增「库存预警数」「今日订单」「履约能力」三列，一眼看出哪家店有问题。
- 行点开为**详情抽屉**（不是跳页），四个 Tab：
  1. 档案与营业时间
  2. 履约设置（自提/配送、时段、配送范围、运费）
  3. 库存（搜索 + 就地改库存 + 库存流水）
  4. 看板（今日/近 7 天，复用现有看板数据）
- 抽屉底部「关联会员」：从客户中搜索并绑定该店负责人（见 4.1），绑定后该会员在小程序看到门店中心。

### 3.4 权限与账号

- PC 端仅保留 SUPER / OPS / CS / WMS，**彻底禁止 STORE 登录**：登录接口直接拒绝，提示「门店操作请使用小程序门店中心」。
- 门店业务在 PC 全部可见：订单、自提、配送、门店、库存都按全量展示，用「门店」列 + 多选筛选收窄，不需要任何门店身份。
- 删除 STORE 的 PC 菜单与路由；`AdminRole` 枚举保留以兼容历史日志与旧数据。

## 4. 小程序「门店中心」

### 4.1 入口与身份

- 个人中心「我的」页在「我的订单」卡片下方新增一行：**门店中心**，副标题显示 `昆明五华店 · 店长`。
- 门店账号由总部在 PC 创建：创建门店时从会员中**关联一名会员**作为该店负责人，绑定后这位会员登录小程序即可看到「门店中心」。
- 不引入邀请码、扫码绑定、独立账号密码。普通顾客看不到该入口，避免污染个人中心。
- 换人/离职：总部在门店详情里「更换关联会员」或解绑，原会员立即失去入口；解绑与换绑都写入操作日志。

### 4.2 页面结构

```
门店中心（工作台）
├─ 待办卡片：待接单 n · 待核销 n · 配送中 n · 库存预警 n
├─ 今日经营：支付订单 / GMV / 退款
├─ 主按钮：扫码核销（大按钮，拇指区）
├─ 快捷入口：接单 · 库存 · 门店信息
└─ 底栏：工作台 / 核销 / 配送 / 我的门店
```

| 页面 | 关键内容 | 体验要点 |
| --- | --- | --- |
| 工作台 | 待办数字、今日 KPI、扫码核销大按钮 | 首屏不滚动即可看到「要做什么」；数字可点，直达对应列表 |
| 核销 | 扫码 / 输 8 位码 → 结果页 | 成功页大字 + 顾客昵称 + 商品件数 + 「继续核销」；重复核销明确提示「已于 10:32 核销」 |
| 配送 | 待接单 / 配送中 / 已完成 | 卡片含地址、时段、电话一键拨号；接单 → 送达两步；支持连续接单 |
| 库存 | SKU 搜索、库存/安全库存、± 调整、流水 | 就地加减，键盘弹起不遮挡；低于安全库存标红 |
| 我的门店 | 营业时间、配送时段、公告、临时打烊开关 | 「临时打烊」二次确认并写明影响（小程序将不再展示可配送时段） |

### 4.3 移动端体验原则

1. **一屏一任务**：每页只服务一个动作，不堆筛选器。
2. **待办优先**：所有列表默认只展示「需要我处理的」，历史记录收进 tab。
3. **大按钮在拇指区**：核销、接单主按钮固定在底部安全区上方。
4. **即时反馈**：操作后 toast + 轻触感；失败给出可重试的明确原因（如「该单已被其他店员接单」）。
5. **弱网可用**：核销与接单请求幂等；失败自动重试 1 次并保留输入；关键页骨架屏。
6. **防误操作**：送达、打烊、批量接单均二次确认，确认文案写明门店名与单量。

## 5. 技术方案

### 5.1 数据模型

不新增账号体系：门店直接关联一名会员，会员登录小程序即拥有门店中心。

```prisma
model Store {
  // …现有字段
  managerUserId String? @unique   // 关联会员（小程序 User），为空表示暂未关联
  manager       User?   @relation(fields: [managerUserId], references: [id], onDelete: SetNull)
}

model User {
  // …现有字段
  managedStore Store?
}
```

- 一个会员最多关联一家门店（`@unique`），一对一，避免「我在哪家店」的歧义；后续需要多店员时再扩展 `StoreStaff` 多对多，不推翻此模型。
- 候选会员必须已绑定手机号，总部按手机号/昵称搜索选择；未绑定手机号的会员不出现在候选列表。
- 删除门店或解绑会员时 `onDelete: SetNull`，不会误删会员。

### 5.2 接口

**PC（总部）**

| 接口 | 说明 |
| --- | --- |
| `GET /admin/customers?keyword=` | 复用现有客户检索，供「关联会员」选择器使用 |
| `POST /admin/stores`、`PATCH /admin/stores/:id` | 新增 `managerUserId` 字段，创建门店时一并关联会员 |
| `PUT /admin/stores/:id/manager` | 更换 / 解绑关联会员（写操作日志） |

**小程序（门店）** `/store-console/*`，鉴权用小程序用户 JWT，并校验 `Store.managerUserId === user.id`：

| 接口 | 说明 |
| --- | --- |
| `GET /store-console/context` | 当前关联门店与是否可进入门店中心 |
| `GET /store-console/summary` | 待办数 + 今日 KPI |
| `POST /store-console/pickups/verify` | 核销（复用 PickupService，幂等） |
| `GET /store-console/deliveries` | 本店配送单列表（分页/状态） |
| `POST /store-console/deliveries/:id/accept`、`/deliver` | 接单 / 送达 |
| `GET/PATCH /store-console/inventory` | 库存列表与调整（含流水） |
| `PATCH /store-console/store` | 营业时间 / 时段 / 公告 / 打烊 |

PC 侧接口保持现有 `admin/*` 不变，仅新增门店多选筛选参数；`/admin/stores/:id/dashboard` 复用为抽屉看板数据源。

### 5.3 兼容与迁移

- 彻底移除 STORE 角色的 PC 登录：登录接口对 `role = STORE` 直接拒绝，并提示「门店操作请使用小程序门店中心」。
- 现有 `AdminStore` 授权关系与 STORE 账号：上线前由总部为每家门店指定关联会员，随后停用全部 STORE 账号；`AdminStore` 保留历史审计，不再参与鉴权。
- 历史 STORE 账号的操作日志不迁移，按原 actorId 保留可查。

## 6. 分期计划

| 阶段 | 内容 | 交付价值 |
| --- | --- | --- |
| **P0**（体验止损） | PC 去门店切换、订单/自提/配送加门店列与筛选、菜单合并、门店详情抽屉（档案/履约/库存/看板）、门店新增「关联会员」 | 总部单页看全部门店，消除「我在哪家店」的困惑 |
| **P1** | 小程序门店中心：入口 + 工作台 + 核销 + 配送 | 门店一线不再依赖电脑，核销/接单手机上完成 |
| **P2** | 库存调整、营业设置、临时打烊、门店看板（移动端） | 门店可自助运营，总部只做审核与配置 |
| **P3** | 收尾：STORE 登录彻底关闭、历史数据核对、埋点与操作日志 | 权限模型单一，审计完整 |

P0 与 P1 可并行；P1 上线前需完成小程序审核（扫码、拨号权限说明）。

**进度**：P0、P1、P2 全部完成（库存查看/预警/调整、营业时间/公告/履约开关、临时打烊、移动端门店看板）；P3 收尾待排期。

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 门店网络差导致核销失败 | 核销接口幂等 + 失败重试 + 结果页可手动重查 |
| 门店负责人变更/离职 | 总部在门店详情更换关联会员，原会员立即失去入口 |
| 会员未绑定手机号无法被检索 | 门店表单里提示「该会员未绑定手机号，请先引导绑定」，不允许保存 |
| 一家门店需要多人操作 | 本期一对一；如确有多人需求，P2 扩展 `StoreStaff` 多对多 |
| 小程序审核类目 | 提前准备「工具-企业管理」类目与扫码/拨号说明 |

## 8. 已确认决策

1. **PC 彻底禁止 STORE 登录**，门店业务全部在 PC 总部视图内可见。
2. **门店账号由总部创建**：创建门店时关联一名会员，该会员在小程序个人中心看到「门店中心」；无邀请码流程。
3. **已定**：P1 库存为只读态（入口含预警数字），P2 起门店可自助调整库存与营业设置；总部保留 PC 端全量配置能力。
