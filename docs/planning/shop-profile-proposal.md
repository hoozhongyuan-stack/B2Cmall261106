# 店铺基础信息设置 提案

> 需求：补齐「店铺基础信息」配置——店铺名称、品牌 Logo、联系方式、业务域名、备案信息等，并让小程序与后台对外展示统一读取。
> 原则：一个配置源、只收真实需要的字段、合规信息可公开检索、不把技术参数和品牌资料混在一起。

---

## 一、现状盘点

### 1.1 已有字段（`ShopConfig`）

| 字段 | 后台「设置 → 店铺信息」 | 小程序 |
| --- | --- | --- |
| 店铺名称 `shopName` | 有 | 登录页、我的页底部 |
| 品牌 Logo `logoKey` | 有（素材库选图） | 登录页方形 Logo；**当前值为空** |
| 店铺简介 `intro` | 有 | 登录页、我的页底部 |
| 客服电话 `servicePhone` | 有 | 我的 → 联系客服（拨号） |
| 包邮门槛 / 运费 / 支付超时 / 售后 / 自动确认 | 有 | 下单、售后规则 |

### 1.2 已有但分散

| 参数 | 当前位置 | 问题 |
| --- | --- | --- |
| 业务域名 `businessDomain` | 设置 → 集成配置 | 属于技术参数，和品牌资料分开；店铺信息页看不到 |
| 用户协议 / 隐私政策 | 小程序内置静态文本 | 正文写死「山野商城」，没有店铺主体和联系方式 |
| 小程序 AppID / 支付商户号 | 设置 → 集成配置 | 合理，保持不动 |

### 1.3 完全缺失

| 类别 | 缺失参数 |
| --- | --- |
| 联系方式 | 客服邮箱、客服微信、服务时间、公司地址 |
| 主体信息 | 公司全称、统一社会信用代码 |
| 备案信息 | ICP 备案号、公安备案号及备案链接 |
| 对外站点 | 官方商城 / H5 地址（用于分享、客服、协议） |
| 资质证照 | 营业执照、食品经营许可证等（P2） |
| 展示入口 | 小程序无「关于我们」页；协议页无主体信息；H5 无备案页脚 |

---

## 二、目标与范围

| 能力 | P1 范围 |
| --- | --- |
| 品牌资料 | 名称、Logo、简介（沿用）+ 后台实时预览登录页效果 |
| 联系方式 | 客服电话（必填）、邮箱、微信、服务时间、公司地址 |
| 主体与备案 | 公司全称、统一社会信用代码、ICP 备案号 + 链接、公安备案号 + 链接 |
| 域名 | 店铺信息页只读展示「业务域名」（来源集成配置），一键跳转修改；新增「官方商城地址」 |
| 对外展示 | 小程序新增「关于我们」页；协议页页脚注入主体与联系方式；H5 页脚展示备案号 |
| 权限 | `SUPER` 可写，其他角色只读 |

**不做（P1）**：资质证照多图、分享封面、地图定位、多语言、主体变更审计。

---

## 三、字段设计

### 3.1 新增字段（全部可空，兼容旧数据）

| 分组 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 联系方式 | `serviceEmail` | String? | 客服邮箱，≤80 |
| 联系方式 | `serviceWechat` | String? | 客服微信 / 企业微信，≤40 |
| 联系方式 | `serviceHours` | String? | 服务时间，如「9:00-21:00」，≤40 |
| 联系方式 | `companyAddress` | String? | 公司地址，≤120 |
| 主体信息 | `companyName` | String? | 主体全称，≤60，如「云南山野商贸有限公司」 |
| 主体信息 | `creditCode` | String? | 统一社会信用代码，18 位大写字母/数字 |
| 备案信息 | `icpNumber` | String? | ICP 备案号，≤40，如「滇ICP备2026000000号」 |
| 备案信息 | `icpUrl` | String? | 备案查询链接，默认 `https://beian.miit.gov.cn/` |
| 备案信息 | `policeNumber` | String? | 公安备案号，≤40 |
| 备案信息 | `policeUrl` | String? | 公安备案链接 |
| 对外站点 | `officialSiteUrl` | String? | 官方商城 / H5 地址，https，≤200 |

### 3.2 复用字段

- `shopName`、`logoKey`、`intro`、`servicePhone` 继续使用，不新建同义字段。
- 交易参数（包邮门槛、运费、支付超时、售后期、自动确认）保持原样。
- `businessDomain` **不复制**到店铺信息，避免两处配置不一致。

### 3.3 「业务域名」与「官方商城地址」的区别

| 参数 | 用途 | 存放 |
| --- | --- | --- |
| 业务域名 `businessDomain` | 微信小程序 request 合法域名 / API 地址 | 集成配置（唯一来源） |
| 官方商城地址 `officialSiteUrl` | 对外展示、分享、客服引导的 H5 站点 | 店铺信息（新增） |

## 四、数据模型

```prisma
model ShopConfig {
  // ...既有字段不动
  serviceEmail    String?
  serviceWechat   String?
  serviceHours    String?
  companyAddress  String?
  companyName     String?
  creditCode      String?
  icpNumber       String?
  icpUrl          String?
  policeNumber    String?
  policeUrl       String?
  officialSiteUrl String?
}
```

迁移：`shop_profile_fields`，仅 `ALTER TABLE "ShopConfig" ADD COLUMN`，无回填、无锁表风险。

## 五、接口设计

### 5.1 公开接口 `GET /shop`

在现有字段基础上追加（空值返回 `null`）：

```
serviceEmail, serviceWechat, serviceHours, companyAddress,
companyName, creditCode, icpNumber, icpUrl, policeNumber, policeUrl, officialSiteUrl
```

- 不改动既有字段名与含义；
- `businessDomain` 不下发 C 端（技术参数）；
- 缓存策略不变。

### 5.2 后台接口 `PATCH /admin/shop`

- DTO 增加上述 11 个可选字段；
- 空字符串统一存 `null`；
- 校验：
  - `servicePhone`：7–20 位，允许数字、`+`、`-`、空格；
  - `serviceEmail`：邮箱格式；
  - `creditCode`：`^[0-9A-HJ-NPQRTUWXY]{18}$`（与国标一致）；
  - `icpNumber` / `policeNumber`：≤40，允许中文与数字；
  - `officialSiteUrl` / `icpUrl` / `policeUrl`：必须 `http(s)://`，域名规则复用集成配置的 `domain()`；
  - 所有文本 trim。
- 后台店铺信息页读取业务域名：复用 `GET /admin/integration`，只取 `businessDomain` 只读展示，不新增接口。

### 5.3 openapi 与类型

- `openapi.yaml` 的 `ShopConfig` schema 补字段、`/admin/shop` PATCH body 补字段；
- `pnpm codegen:api` 重新生成类型。

## 六、后台页面改造

「设置 → 店铺信息」由「基础资料 + 交易参数」扩展为 4 张卡片：

```
店铺信息
├─ 1. 品牌资料
│     店铺名称*、品牌 Logo、店铺简介
│     └─ 右侧：登录页效果预览（Logo + 名称 + 简介 + 按钮）
├─ 2. 联系方式
│     客服电话*、客服邮箱、客服微信、服务时间、公司地址
├─ 3. 主体与备案
│     公司全称、统一社会信用代码
│     ICP 备案号 + 备案链接、公安备案号 + 备案链接
│     官方商城地址
│     └─ 业务域名（只读，来源「集成配置」；附「去修改」链接）
└─ 4. 交易参数（现有字段不变）
```

- 必填仅「店铺名称」「客服电话」，其余选填；
- 保存按钮统一吸底，字段级错误提示；
- 非 `SUPER` 角色整页只读；
- Logo 缺失时预览与小程序一致，用店铺名首字兜底。

## 七、小程序展示

### 7.1 新增「关于我们」页 `pages/about/index`

入口：我的 → 关于我们（列表项，排在「联系客服」之后）。

内容分区：

1. **品牌**：Logo、店铺名称、简介；
2. **联系方式**：客服电话（点击拨号）、客服邮箱（复制）、客服微信（复制）、服务时间、公司地址；
3. **主体与备案**：公司全称、统一社会信用代码、ICP 备案号、公安备案号、官方商城地址（复制）；
4. **版本**：小程序版本号。

规则：

- 未配置的字段整行不展示，不留「未配置」占位；
- 小程序不能直接打开外部链接：备案号 / 网址点击后复制并 toast「已复制」；H5 环境直接 `window.open`；
- 无任何联系与备案信息时，页面只展示品牌区。

### 7.2 协议页

- 用户协议、隐私政策正文中的「山野商城」替换为后台 `shopName`；
- 页脚追加一行：`运营主体：{{companyName}} · 客服电话：{{servicePhone}}`（字段为空则整行省略）。

### 7.3 我的页 / 登录页

- 我的页底部继续展示店铺名称 + 简介；
- 联系客服仍拨号，未配置时保持「未配置」提示；
- 登录页不变（已同步名称 / Logo）。

### 7.4 H5 页脚（P1.5）

H5 环境在页面底部渲染 `ICP 备案号` 与「公安备案」链接，点击打开备案查询站；小程序端不渲染。

## 八、校验与边界

| 场景 | 处理 |
| --- | --- |
| Logo 为空 | 允许保存，登录页/关于我们用首字兜底 |
| 电话为空 | 后台提示必填；小程序「联系客服」显示未配置 |
| 备案号格式不合法 | 仅长度与字符校验，不做备案真实性校验 |
| 外链协议 | 仅接受 `http/https`，禁止 `javascript:` 等 |
| 文本换行 | 地址、简介允许，统一 trim 并折叠连续空白 |
| 权限 | 读取：`SUPER/OPS/CS/WMS`；写入：`SUPER` |
| 敏感字段 | 以上均为公开展示信息，无密钥类字段 |

---

## 九、兼容与迁移

1. 新增列全部可空，旧数据 `null`，前端按「未配置」处理；
2. `GET /shop` 只增不改，旧客户端不受影响；
3. 「关于我们」页面为新增路由，不影响现有页面；
4. 协议页改为读取 `/shop`，失败时回退到内置默认文案，避免白屏；
5. 不做数据回填；上线后由运营在后台补齐。

## 十、测试与验收

**契约测试**

- `PATCH /admin/shop` 写入新增字段并回读一致；
- 邮箱、信用代码、URL 非法时 400；
- 空字符串保存为 `null`；
- `GET /shop` 返回新增字段，且不返回 `businessDomain`；
- 非 `SUPER` 写入 403。

**E2E**

1. 后台填写联系方式、主体、备案并保存 → 刷新后回显；
2. 小程序「我的 → 关于我们」展示全部已配置信息，未配置项不出现；
3. 点击客服电话触发拨号（H5 断言 `tel:` 链接或 toast）；
4. 协议页页脚展示主体与电话；
5. Logo 清空后登录页用首字兜底；
6. 「业务域名」只读展示且与集成配置一致。

**验收标准**

- 后台一次保存全部生效，无需重启；
- 小程序无需发版即可读到最新配置（接口缓存 ≤1 分钟）；
- 任何字段留空都不导致页面报错或空白。

## 十二、决策结论

已确认，可按 P1 实施：

1. **业务域名**：店铺信息页只读引用「集成配置」，附「去修改」链接，不复制字段。
2. **必填范围**：仅「店铺名称 + 客服电话」必填，其余全部选填。
3. **资质证照**：放到 P2，P1 不做上传与展示。
4. **关于我们入口**：放在「我的」列表内，排在「联系客服」之后。
