# PC 后台体验审计与优化提案

> 方式：以超级管理员身份在浏览器中实际操作，覆盖 1440×900 与 1280×720 两种常见办公分辨率；
> 覆盖登录、数据概览、商品列表/新建、积分商城、订单列表/详情、客户列表/详情、积分规则、角色列表/新建、店铺信息、小程序与支付、页面装修、底部导航、素材库。
> 本文只记录体验问题与改造方案，不涉及业务规则变更。

## 一、总体判断

后台的模块分组、卡片式布局、表单风格和权限反馈已经比较统一，基础可用性良好。当前主要问题不在“好不好看”，而在**高频操作效率**与**小屏办公适配**：

- 1280/1366 笔记本上，多列表格被压扁，出现中文竖排、日期折行、地址逐字换行。
- 登录页直接预填并展示种子账号密码，正式环境存在明显风险。
- 多个高频页面仍依赖“找按钮、点更多、再确认”，缺少行内操作、快捷筛选与明确反馈。
- 空数据、零值、测试数据在仪表盘中混在一起，影响经营判断。

体验评分（5 分制，主观）：

| 维度 | 评分 | 说明 |
| --- | --- | --- |
| 信息架构 | 3.5 | 模块分组清晰，但侧栏仅图标，首次使用靠猜 |
| 操作效率 | 3.0 | 列表筛选与批量能力有，但高频动作路径偏长 |
| 视觉一致性 | 4.0 | 卡片、表单、按钮基本统一 |
| 小屏适配 | 2.5 | 1280 下表格与筛选区明显拥挤 |
| 反馈与可恢复性 | 3.0 | 错误以 Toast 为主，缺少字段级定位与撤销 |
| 上线安全性 | 2.0 | 登录页暴露并预填演示账号 |

## 二、关键问题

### P0：上线前必须处理

**1. 登录页预填管理员账号，并明文展示种子账号密码**

- 现状：账号、密码已预填；页面下方列出 `admin / ops / cs / wms` 四组账号和密码。
- 影响：任何能打开后台登录页的人都能直接进入超管；正式环境不可接受。
- 方案：
  - 仅 `import.meta.env.DEV` 时展示演示账号，生产构建不渲染。
  - 生产环境账号、密码输入框默认留空。
  - 首次部署改为初始化向导或一次性邀请链接，不写死默认密码。

**2. 1280/1366 笔记本下表格可读性差**

- 现状：客户列表「等级」列显示为「常 / 客」两行；「最近下单」「注册时间」折成两到三行；订单列表「收货信息」逐字换行。
- 原因：表格 `width: 100%` 且无最小列宽，浏览器优先压缩列宽而不是横向滚动。
- 方案：
  - 给 `DataTable` 增加 `minWidth` 约定：客户 ≥ 1180px、订单 ≥ 1320px、商品 ≥ 1080px，外层容器横向滚动。
  - 低优先级列（SKU 数、注册时间、支付时间等）在 `<1440px` 收起，放入行展开或详情页。
  - 数字、日期、金额列统一 `white-space: nowrap`；文本列使用省略号 + `title`。
  - 表头吸顶，长列表滚动时保留列语义。

**3. 客户列表筛选区换行错位，且输入即请求**

- 现状：1440 下「重置」被挤到第二行；1280 下「最高消费 / 搜索 / 重置」散落在第二行。
- 现状：最低/最高消费每输入一位数字就触发一次列表请求。
- 方案：
  - 把日期区间、金额区间做成成对控件（一个容器内两个输入 + 分隔符），减少独立控件数量。
  - 关键字、金额输入改为「回车/点击搜索」触发；下拉筛选可即时生效，但统一展示“筛选中”反馈。
  - 筛选区右侧固定「查询 / 重置」，禁止散落换行。
  - 已生效条件以 chips 展示，可单点移除。

### P1：高频操作效率

**4. 侧栏仅图标，依赖悬浮才能看到菜单名**

- 现状：一级导航只有 9 个图标，悬浮才出现二级菜单；新员工需要逐个试探。
- 方案：
  - ≥1280px 时提供“展开侧栏”模式，图标 + 一级名称；记住用户选择。
  - 保留悬浮二级菜单，但增加首次进入的引导提示。
  - 当前所在模块增加更强的选中态与标题联动。

**5. 新建商品：长表单缺少字段级反馈与素材预览**

- 现状：保存失败只在顶部弹 Toast；不滚动、不聚焦到出错字段。
- 现状：主图/详情图只有“从素材库选择”按钮，无缩略图预览。
- 现状：SKU 区域从第二屏开始，定价与库存信息离基础信息较远。
- 方案：
  - 校验失败：字段红框 + 行内错误文案，自动滚动并聚焦第一个错误字段。
  - 图片选择后直接展示缩略图、排序与删除，未选时给出尺寸建议。
  - SKU 卡片支持折叠摘要（规格 / 价格 / 库存），默认展开第一个。
  - 底部保存条保留，但增加“未保存更改”提示与离开拦截。

**6. 订单列表列多、动作远，状态色偏弱**

- 现状：订单号、客户、商品、金额、状态、门店/履约、收货信息、下单时间、支付时间、操作同屏；1280 下信息互相挤压。
- 现状：查看详情需要点击最右侧「查看」，整行不可点。
- 方案：
  - 整行可点击进入详情；操作列只保留当前状态最关键动作（发货 / 查看）。
  - 收货信息列合并为“收货人 + 城市”，完整地址进详情。
  - 状态使用更明确的色块 + 图标；待发货、售后中使用高对比色。
  - 增加快捷筛选 chips：待发货、售后中、今日订单。

**7. 积分兑换订单详情：零值信息与空态占用注意力**

- 现状：积分订单金额区仍展示「会员优惠 -¥0.00」「优惠券 -¥0.00」「运费 ¥0.00」。
- 现状：物流信息整张卡只有「尚未发货」，占用大块高度。
- 现状：「整单退款」与「发货」并列在顶部，破坏性操作过于显眼。
- 方案：
  - 零值行按订单类型隐藏；积分订单突出「消耗积分 / 加价金额 / 实付」。
  - 空物流改为一行紧凑提示，发货后再展开卡片。
  - 退款收进「更多」菜单，并二次确认；确认弹窗展示退款金额与返还积分。

**8. 积分商城列表缺少经营信号**

- 现状：只有兑换价、库存、已兑、限兑；没有库存预警、上下架快捷操作与排序。
- 现状：无图商品与测试商品占据首屏。
- 方案：
  - 库存 ≤ 5 显示预警标签；售罄商品置灰并显示“已兑完”。
  - 兑换价明确区分「纯积分」「积分 + ¥金额」。
  - 行内提供上架/下架；增加按库存、已兑、更新时间排序。
  - 演示/测试商品增加标记或清理入口，避免混入正式列表。

**9. 数据概览：空数据与测试数据影响判断**

- 现状：7 日趋势中 5 天为 0，图表只剩两根很高的柱子，视觉上像异常。
- 现状：热销商品混入 0 元 E2E 积分商品。
- 方案：
  - 无数据时显示「近 7 日暂无支付」空态，而不是零值柱状图。
  - 柱状图增加环比、客单价、退款率等经营指标；点击柱子可跳转对应日期订单。
  - 明确区分测试数据（`E2E`、`契约` 前缀）并在统计中排除或提供“包含测试数据”开关。
  - 待办卡片支持点击直达对应筛选结果。

**10. 角色权限页：58 项权限缺少检索与模板**

- 现状：权限全部平铺，新增角色需要逐项勾选；编辑时难以快速确认已选项。
- 方案：
  - 增加权限搜索、 「仅看已选」、分组折叠/展开、全选/清空。
  - 提供「复制现有角色」作为新角色起点。
  - 保存前展示“将获得哪些菜单与关键操作”的摘要。

### P2：一致性与细节

**11. 表单校验与反馈不统一**

- 统一为：字段级错误 + 顶部汇总（可选）+ 保存成功 Toast；失败后聚焦第一个错误。
- 危险操作统一二次确认，确认按钮使用危险色，文案包含对象名称与影响范围。

**12. 设置页空间利用不均**

- 「小程序与支付」表单宽度约 460px，1440 下右侧大片留白；「店铺信息」则是宽表单。
- 方案：设置类页面统一最大宽度（如 880px）居中，或左表单 + 右侧说明/状态卡；保存按钮吸底。

**13. 加载与空态**

- 列表加载目前多为文字「加载中…」，建议统一骨架屏；空态提供下一步动作（新建 / 清除筛选 / 去配置）。
- 表格、卡片、弹窗的圆角、阴影、间距继续沿用现有 token，避免新页面各自定义。

**14. 文案与术语**

- 「积分仅记录，不参与订单抵扣」在积分商城上线后容易误解；建议补充“可在积分商城兑换商品”。
- 角色迁移说明（“由原商品运营角色迁移…”）属于内部信息，正式环境应改为业务描述。

## 三、实施建议

### 第一阶段：上线安全与小屏可用

1. 登录页移除生产环境预填与种子账号展示。
2. `DataTable` 支持 `minWidth`、横向滚动、表头吸顶、列优先级。
3. 客户/订单/商品列表按 1280 与 1440 两档调整列显隐。
4. 客户筛选区重排，金额/日期输入改为显式查询，避免输入即请求。

### 第二阶段：高频路径提效

1. 侧栏支持展开模式（图标 + 名称）。
2. 商品表单字段级校验、图片预览、SKU 折叠摘要。
3. 订单列表整行点击、关键动作前置、状态强化。
4. 积分订单详情隐藏零值行、退款收进更多菜单。
5. 积分商城库存预警与行内上下架。

### 第三阶段：经营与权限体验

1. 仪表盘空态、环比指标、测试数据过滤与图表下钻。
2. 角色权限搜索、仅看已选、复制角色、权限摘要。
3. 统一骨架屏、空态动作与危险操作规范。

## 四、验收标准

| 项 | 标准 |
| --- | --- |
| 登录安全 | 生产构建不出现任何演示账号、密码与预填值 |
| 小屏适配 | 1280×720 下客户/订单/商品列表无中文竖排、无逐字换行，允许表格内横向滚动 |
| 筛选体验 | 筛选区不出现孤立换行；金额输入不逐键请求；已生效条件可见可移除 |
| 表单反馈 | 校验失败定位到字段并聚焦；图片选择后有缩略图；离开未保存表单有拦截 |
| 订单效率 | 整行可进详情；关键动作不超过一次点击；状态色可快速区分 |
| 积分订单 | 零值信息不展示；退款有二次确认并说明积分返还 |
| 仪表盘 | 无数据有明确空态；测试数据不混入经营指标 |
| 角色权限 | 支持搜索、仅看已选、复制角色与保存前摘要 |

---

## 五、建议不做

- 不引入新的 UI 组件库，继续使用现有 tokens 与组件，避免视觉体系分裂。
- 不做全屏式驾驶舱或复杂动画，后台以稳定、快速、可扫读为优先。
- 不在本期增加多级审批、工作流引擎等重能力，先把高频路径打磨顺。
