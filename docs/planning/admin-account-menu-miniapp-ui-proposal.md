# 设置精简、账号菜单与小程序 UI 规范化 提案

> 反馈：①「设置」里的集成配置 / 支付设置疑似重复，需要精简；②小程序页面乱，字号、居中、组件需要统一；③子账号、操作日志独立到「账号」菜单。
> 原则：一个配置只留一个入口；菜单按使用场景分组；字号只取一套刻度；页面只用一个内容容器；空态/加载态只用统一组件。

---

## 一、现状盘点

### 1.1 「设置」菜单 9 项

| 菜单 | 路由 | 内容 | 问题 |
| --- | --- | --- | --- |
| 店铺信息 | `/settings/shop` | 品牌资料、联系方式、主体备案、交易参数 | 合理 |
| 集成配置 | `/settings/integration` | 小程序登录、微信支付、订阅消息 7 个模板 + 字段映射 JSON、域名 | **一页四类内容，约 570 行** |
| 小程序发布 | `/settings/miniapp-release` | 上传代码、体验版 | 合理，依赖集成配置 |
| 运费模板 | `/settings/freight` | 运费规则 | 合理 |
| 支付设置 | `/settings/payment` | **只读**展示集成配置里的支付字段 + 固定说明 + 检查清单 | **重复，且无任何可编辑项** |
| 系统状态 | `/settings/system` | 磁盘/备份、订阅消息日志、退款对账 | 合理 |
| 物流公司 | `/settings/express` | 物流字典 | 合理 |
| 子账号 | `/accounts` | 账号管理 | **与配置无关，放错分组** |
| 操作日志 | `/logs` | 审计记录 | **与配置无关，放错分组** |

### 1.2 重复判定：支付设置 = 集成配置的只读镜像

| 字段 | 集成配置 | 支付设置 |
| --- | --- | --- |
| 支付渠道 provider | 可编辑 | 只读展示 |
| 商户号 MchID | 可编辑 | 只读展示 |
| 证书序列号 / 回调地址 / 公钥 ID | 可编辑 | 未展示 |
| APIv3 密钥 / 商户私钥 / 微信支付公钥 | 上传 | 只读「已上传/未配置」 |
| 配置检查清单 | 无 | 有 |

结论：支付设置没有任何独立写入能力，只是集成配置的摘要页，属于菜单级重复；同时集成配置把「登录、支付、通知、域名」四件事塞进一页，需要填 4 个密钥文件 + 7 个模板 ID + 一段 JSON，低频且门槛高，不适合平铺。

### 1.3 小程序 UI 抽样（32 个页面）

| 问题 | 证据 |
| --- | --- |
| 字号刻度混用 | 全项目出现 **24 种字号**（10/11/12/13/14/15/16/17/18/20/21/25/26/28/30/32/34/36/38/40/44/48/52/56/64/72/84px），其中 **14 个文件**在用 10–21px 的「物理像素刻度」：门店列表、门店中心 5 个页、分类、登录、商品详情、优惠券、售后详情、微页面渲染器、底部导航 |
| 层级颠倒 | 门店列表店名 `16px`、地址却用全局 `.small`（`24px`）→ **辅助信息比标题大**（截图已复现） |
| 页面参考线跳动 | 内容容器横向内边距：首页/个人中心 `32px`，门店列表 `16px`，门店中心 `12–16px`，分类搜索条贴边 `12px` |
| 裸色值 | `#b26a00`、`#fdecec`、`#fff`、`#4a6b3c`、`#e7e2d8` 等散落在页面 CSS，与品牌 token 不一致 |
| 组件复用不足 | `Empty` 仅 15 个页面使用、`Loading` 27 个，但仍有约 20 处手写「暂无 / 加载中」；卡片、行、统计块、搜索条各页各写一套 |
| 居中问题 | 分类页空态在右侧内容区偏移；门店列表搜索条与卡片左边界不一致；底栏按钮与安全区处理不统一 |

## 二、方案

### 2.1 设置精简（推荐方案 A：合并支付设置）

**菜单调整**

| 调整前（9 项） | 调整后（6 + 2 项） |
| --- | --- |
| 店铺信息 | 设置 · 店铺信息 |
| 集成配置 | 设置 · **小程序与支付**（原集成配置，页内分 Tab） |
| 小程序发布 | 设置 · 小程序发布 |
| 运费模板 | 设置 · 运费模板 |
| ~~支付设置~~ | **删除菜单**，路由重定向到 `/settings/integration?tab=payment` |
| 系统状态 | 设置 · 系统状态 |
| 物流公司 | 设置 · 物流公司 |
| 子账号 | **账号 · 子账号** |
| 操作日志 | **账号 · 操作日志** |

**集成配置页重构**

- 页头固定「保存配置」，页内 4 个 Tab，每个 Tab 一屏内可完成：
  1. 小程序（AppID / AppSecret / 代码上传密钥）
  2. 微信支付（渠道、商户号、证书序列号、回调、公钥 ID、3 个密钥文件）
  3. 订阅消息（7 个模板 ID、字段映射 JSON，JSON 默认折叠）
  4. 域名与地址（API 地址、业务域名）
- 微信支付 Tab 顶部增加**状态条**：渠道 / 商户号 / APIv3 密钥 / 商户私钥 / 公钥 五项 ✓、! 徽标；原「支付设置」的检查清单收纳为「查看配置检查」折叠区。
- 保留既有约定：密钥不回显、留空不修改、上传文件 ≤200KB。
- 标题与描述改为「小程序与支付」，面包屑同步。

**为什么选 A 而不是 B**

- 方案 B（保留两个菜单，把支付设置改成可编辑）会增加一次跳转，且同一组字段仍有两个入口；支付参数只有 5 个输入 + 3 个文件，不值得单独一页。
- 合并后「设置」只剩配置类入口，菜单从 9 项降到 6 项。

### 2.2 「账号」菜单独立

- 新增一级分组「账号」（放在「设置」之后），含：
  - 子账号 `/accounts`（`SUPER`）
  - 操作日志 `/logs`（`SUPER` / `OPS` / `CS`）
- 新增账号图标；菜单、面包屑均由 `Layout.tsx` 的数据驱动，无需额外逻辑。
- 「设置」组只保留店铺与系统配置，语义变清晰。

### 2.3 小程序 UI 规范

**① 字号只保留 9 级（750 设计稿刻度）**

| Token | 750 值 | 约合 375 | 用途 |
| --- | --- | --- | --- |
| `--fs-hero` | 64 | 32 | 大图标、超大数字 |
| `--fs-amount` | 48 | 24 | 金额、大数字 |
| `--fs-display` | 40 | 20 | 登录标题、看板数字 |
| `--fs-title` | 34 | 17 | 页面主标题 |
| `--fs-section` | 30 | 15 | 区块标题、主按钮 |
| `--fs-body` | 28 | 14 | 正文、列表主标题 |
| `--fs-secondary` | 24 | 12 | 辅助说明、副标题 |
| `--fs-caption` | 22 | 11 | 标签、角标、时间 |
| `--fs-micro` | 20 | 10 | 极小说明（仅限角标） |

与现有全局 `.title 34 / .section-title 30 / page 28 / .small 24 / .tiny 22` 对齐，改造面最小；刻度以外的散值（如 11/12/14/18/26/32/36/38/44/52/56/72/84）全部禁用。

**② 页面容器与对齐**

- `.page` 作为唯一页面容器，横向固定 `32px`；通栏区块用 `.page--flush`，其内部内容仍按 `32px` 对齐。
- 搜索条、筛选条、Tab 条、列表卡片、区块标题统一与 `.page` 同一条左右参考线。
- `.empty` / `.loading` 统一宽 `100%` 且居中（修复分类页右侧内容区偏移）。
- 行容器统一 `align-items: center`；金额/数字统一 `font-variant-numeric: tabular-nums`。
- 底部固定操作条统一 `.bottom-bar`（左右 32、含 `env(safe-area-inset-bottom)`），可点击区域 ≥ 88px。

**③ 颜色只用 token**

- 页面 CSS 禁止裸色值；补充语义 token：`--warn-soft`、`--ok-soft`、`--brand-deep` 等，替换 `#b26a00`、`#fdecec`、`#4a6b3c`、`#e7e2d8`。
- 微信品牌色等确实无法 token 化的，集中定义在一个 `:root` 变量里并注释来源。

**④ 组件复用（扩展 `components/common.tsx`）**

| 新组件 | 替换对象 |
| --- | --- |
| `PageState`（loading / empty / error 三态） | 20 处手写空态、各页零散 loading |
| `Cell`（标题 + 值 + 箭头 + 点击） | 个人中心菜单、设置类列表 |
| `SectionHeader`（标题 + 右侧操作） | 「我的订单 · 全部订单」等区块头 |
| `StatTile` | 个人中心 3 格、门店中心 4 格待办、看板数字 |
| `SearchBar` | 分类、门店、搜索页三套搜索条 |
| `Tag`（已存在，补 `--warn/ok` 变体） | 门店「可自提/可配送」、订单状态 |

**⑤ 逐页改造清单**

| 优先级 | 页面 | 动作 |
| --- | --- | --- |
| P0 | 门店列表 | 店名 16→28、地址回到 24、搜索条与卡片对齐 32、Logo 尺寸统一 |
| P0 | 门店中心（5 个 CSS） | 20/12/11px 整体升到 750 刻度；hero 与内容同 32 对齐；待办改用 `StatTile` |
| P0 | 分类 | 分类文字 18→22、排序 20→24；空态居中；搜索条贴边修正 |
| P0 | 登录 | 20px 文案升到 22/24；按钮与表单对齐 |
| P1 | 微页面渲染器、底部导航 | 统一到 750 刻度；**需同步核对后台装修预览的缩放**，避免预览与真机不一致 |
| P1 | 商品详情、购物车、结算、优惠券、售后详情 | 文本升到刻度、价格 `tabular-nums`、按钮统一 `.btn` |
| P2 | 其余页面 | 空态/加载态换 `PageState`、边距与颜色 token 化 |

**⑥ 防回归（接入 lint）**

新增 `scripts/check-miniapp-ui.mjs`，在 `pnpm lint` 中执行：

- `font-size` 只允许 9 级刻度值（`tokens.css` 除外）；
- 页面/组件 CSS 禁止 `#hex` 色值；
- 页面级 CSS 不允许重定义 `.card`、`.btn`、`.list-item` 等基础类（只能做布局覆写）。
- 现有违规先加入白名单，随逐页改造递减至 0。

## 三、验收标准

| 项 | 标准 |
| --- | --- |
| 后台菜单 | 设置 6 项 + 账号 2 项；`/settings/payment` 自动跳转支付 Tab；面包屑正确 |
| 集成配置 | 4 个 Tab 均可查看与修改；页头/页尾保存按钮统一提交全部字段；支付状态条与检查清单可用；密钥回显规则不变 |
| 小程序字号 | 审计脚本 0 违规；页面内字号只出现 9 级刻度 |
| 对齐 | 375 / 390 / 414 宽度下无横向溢出，内容左右边距均为 32，空态居中 |
| 组件 | 关键页空态/加载态全部使用 `PageState`；搜索条统一 `SearchBar` |
| 回归 | `pnpm verify` 全绿；全量 E2E 通过（更新集成配置标题断言）；关键页截图验收 |

---

## 四、实施顺序

1. 菜单与路由（`Layout.tsx`、`App.tsx`、删除 `PaymentSettings.tsx` + 重定向）——低风险，先落地。
2. 集成配置改 Tab + 支付状态条/检查清单。
3. 小程序新增字号/颜色 token、`PageState` 等 6 个组件、UI 审计脚本。
4. P0 页面改造（门店列表、门店中心、分类、登录）→ P1 → P2。
5. 全量 E2E、`pnpm verify`、关键页截图验收。

---

## 五、不做（本次范围外）

- 不调整角色权限模型，只移动菜单位置；子账号与日志接口保持不变。
- 不重构支付后端，支付参数仍走 `/admin/integration`。
- 不重写微页面渲染逻辑，仅统一视觉刻度（预览缩放联动需单独验证）。
- 不做暗色模式、主题换肤、小程序端多语言。
- 不重排后台其他模块（订单、商品等）的视觉。
